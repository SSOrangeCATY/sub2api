# 进货价计费身份

计费身份独立于管理员角色和分组访问权限。用户的 `billing_identity`
可设为 `standard`（普通计费）或 `purchase`（进货价身份组）。加入进货价
身份组不会授予管理员权限，也不会开放原本不可访问的分组。

## 后台入口

在 **用户管理 → 创建用户 / 编辑用户 → 计费身份** 中选择进货价身份组。
用户列表显示身份标记。修改身份会失效该用户的 API Key 认证缓存。
仅完整管理员能改变计费身份；受限管理 API Key 不能执行此操作。

## 计费规则

进货价用户按本次最终实际使用的账号收费：

```text
实际扣费 = 账号统计成本基础价 × 实际账号的计费倍率
```

账号统计成本沿用现有账号成本规则，包括适用的渠道规则、模型映射、
时间价卡及缓存等费用；没有账号统计成本覆盖时，沿用现有倍率前基础价。
不再叠加分组销售倍率、个人专属倍率或销售利润控制。
兜底切换后使用接管账号的成本与倍率，不能承诺固定的 0.075x 等倍率。
模型广场、API Key 分组选项和可用渠道页面因此显示“动态进货价”。
余额、订阅和 API Key 额度按同一实际费用扣减。

在途余额预留使用已解析的平台及候选账号中的最高采购成本估算。
无法定价时遵循既有在途预留的 fail-open / fail-closed 配置，不能将未知价
当作免费。批量生图在提交时固定账号成本、倍率及上游批处理折扣快照，
结算只计成功项，后续改价不改变已提交任务。

本功能不执行币种转换，也不把人民币余额当作美元余额换算。
采购成本价卡必须和本站余额使用同一计价单位。

## 清理旧个人倍率

数据库结构迁移 `251_billing_identity.sql` 仅新增身份字段及迁移备份表，
不会在启动时自动改变用户身份或清理个人倍率。

完整管理员可在 **用户管理 → 迁移至进货价身份组** 确认执行，或调用：

```http
POST /api/v1/admin/users/billing-identity/migrate
Content-Type: application/json

{"confirm": true}
```

操作在一个事务中锁定旧倍率及相关用户，先将原倍率和原身份备份到
`billing_identity_migrations`，再把设置过个人倍率的存活用户加入进货价
身份组，并清除全站个人倍率。保留用户的 RPM 覆盖、余额、角色和分组
访问权限；仅删除倍率和 RPM 都为空的旧行。失败则整体回滚，重复执行
不会重复迁移无倍率的用户。响应包含备份 ID、迁移用户数和清理倍率数。

原个人倍率的大小不转为新的身份倍率；例如原 0.1x 和 0.5x 的用户都会
改为跟随实际账号采购成本。迁移前应核对管理员确认对话框的说明。
新的个人倍率写入已停用；原 RPM 限流功能继续使用。

备份表含用户标识及旧计费配置，仅保留在数据库内，不导出到公开仓库。
如需恢复应先核对备份 ID 和迁移后人工修改，按既有数据库恢复流程执行；
不能在有新请求扣费时直接回滚余额或全表覆盖。
