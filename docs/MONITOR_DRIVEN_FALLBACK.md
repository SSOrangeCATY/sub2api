# 渠道监测驱动的兜底分组

## 配置与使用

1. 保留独立业务分组，例如 A（0.075x）、B（0.35x）、C（0.3x），分别绑定各自账号。三个业务组使用相同的平台。
2. 在「渠道监控」为业务分组配置监控，分组名称须完全一致（区分大小写），provider 须与业务组网关协议兼容，模型须覆盖实际请求模型。V1 使用直接绑定该业务组的专用 Key，不能使用兜底入口的 Key。
3. 在「分组管理 → 创建分组 / 编辑分组 → 分组类型」选择「兜底分组」，按 A → B → C 的顺序添加业务组。顺序可调整，最多 20 项。
4. 把对外使用的 API Key 绑定到兜底入口。入口本身不绑定账号，也不需要复制 A 的账号。入口权限代表管理员明确授权其可路由的目标。
5. 「分组管理」「渠道监控」以及用户「渠道状态」显示兜底入口当前会选择的业务组。可输入模型查看该模型的路由；未指定模型时只是默认监控模型的概览。用户只能查看自己可使用的入口，不会收到其余候选链。

本功能实现的是按渠道健康状态选择业务组。每个新请求重新按优先级选择，监控健康读取缓存最多 5 秒。A 明确故障时跳过 A，B 也故障则继续 C；A 恢复后新请求重新优先选择 A。不会迁移已经开始输出的请求。

## 健康状态与探测独立性

- `failed` / `error`：跳过该业务组。
- `operational` / `degraded`：可以路由。单纯延迟偏高不会强制切走。
- `unknown`：仍可尝试该业务组，界面显示未知，不能据此认定健康。适用于未覆盖的模型、监控关闭、读取失败、样本不足或过期。
- 同组同模型有多条有效监控时，任一健康优先，其次降级；全部明确失败才判失败。无关模型或不兼容 provider 的监控不参与聚合。
- V1 最新结果超过两倍（间隔 + 抖动）或至少 2 分钟后失效。探测直接请求业务组，避免 A 已经切到 B 后仍把 B 的成功记录为 A 健康。使用外部 Key 时需管理员自行确保监控真正指向对应业务组。
- V2 使用实际目标组、请求模型最近 5 分钟的被动错误率，遵循现有最小样本量和错误阈值；不以 TTFT / 缓存分数触发切换。快照有效期为刷新间隔加 1 分钟（至少 2 分钟），允许最多 1 分钟的未来时钟偏差，超出后无效。V2 没有独立主动探测：旧失败证据过期后回到未知，允许重新尝试 A，不代表已主动验证恢复。需要主动恢复判断时使用 V1 并为各业务组配置独立探测。

请求到达与下一次探测之间仍可能出现故障窗口。业务组内部沿用账号调度、首输出超时与轮转；跨组选择使用最近渠道监控结果，不承诺在同一个已经发送的请求内无损重放到下一组。

## 校验、计费与边界

- 只接受同平台、启用的普通业务组；不允许订阅组、组合平台、兜底组互相嵌套、重复目标或自引用。入口不能叠加客户端/无效请求降级规则；目标不能启用 ClaudeCodeOnly 或无效请求降级，未启用 ClaudeCodeOnly 的旧客户端降级 ID 不参与普通请求选路。
- 有绑定账号的业务组不能直接转换成兜底入口。后端在事务内锁定并检查，账号绑定路径同时校验业务组类型，避免并发绑定造成入口拥有被忽略的账号。
- 目标删除、停用、类型不兼容、模型不允许或没有可调度账号时跳过；没有目标可用则返回 HTTP 503，不偷偷切到未授权组。
- 入口与目标的模型白名单都生效。API Key 与用户身份保留，定价、倍率、目标组限额/RPM、用户在目标组的 RPM 覆盖、粘性会话和用量记录按实际目标组执行。入口的价格设置不会固定兜底价格；从 0.075x 切到 0.35x 时按目标组计费。
- WebSocket 在首帧拿到模型后选路；每轮重新检查。目标变化或不可用时关闭并要求重连（1013），不在同一连接中跨账号迁移会话。
- 视频、Gemini 长任务/缓存、Live 会话及异步图片批次等需要固定资源归属的接口，创建及控制时拒绝兜底入口 Key，要求使用业务组 Key，以免路由变化后无法查询或结算资源。普通无状态文本/流式请求可以使用兜底入口。
- 管理端路线明细需要 `groups.read`；用户端使用现有可用分组权限限制入口，并隐藏完整候选链。路由面板每 15 秒刷新，隐藏页面时停止轮询。
