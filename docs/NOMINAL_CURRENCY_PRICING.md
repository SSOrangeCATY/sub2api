# 原币数值导入美元价卡

## 业务定义

经营者确认的规则是数值等额记账：上游价目写 ¥1，本站基础价记为 $1。不是按外汇市场汇率换算，也不代表两种法定货币的购买力相同。业务倍率、分时价格、采购成本倍率继续独立计算。例如 100 万输入 token 的来源价为 ¥1、销售倍率 0.4，则扣费数值为 $0.4；采购用户按实际选中账号的采购价及账号倍率结算。

系统统一保存和结算美元数值。`source_currency` 只记录经营者把哪个单位的价目数值导入了美元覆盖价；保存后的每个非空价格字段已经是最终的 USD 单价，不在请求路径上再次转换。空字段仍使用既有 USD 默认价。因此部分覆盖也不会要求把默认美元价假称为原币价格。

## 原有行为分析

- `BillingService` 的模型单价、余额扣费、API Key 配额、预估和成本记录使用 USD 数值，没有逐请求的人民币汇率步骤。
- 默认 DeepSeek 价格来自美元目录/内置美元价，并有默认目录专用的峰谷规则。渠道与分组的显式定价经过既有统一解析器覆盖默认值，保留经营者自定义的分时语义。
- 2026-11-02 的运维记录已通过独立渠道价卡，把人民币数字直接保存为 per-token 数字。其金额效果就是数值等额记账，之前没有来源币种元数据。原记录也说明经营者历史上把平台数值视为人民币额度；本功能不重新解释或重算已有余额、充值及历史账单。
- 采购用户使用选中账号的采购成本；普通用户使用实际路由目标的销售价及倍率。清空兜底入口的固定倍率后会跟随实际目标，入口不再额外叠加倍率。

## 实现边界

沿用 `Group → Channel → 默认目录` 的价格解析器和现有扣费命令，不添加另一套货币结算器。

1. 每条分组价卡、渠道价卡及采购规则价卡可保存 `source_currency`。空值保留旧价卡未知来源的语义，不自动标注旧数据。非空值为大写三字母单位标识。不会读取实时汇率，也不改变价格值。
2. 编辑器展示“1 来源单位 = 1 USD 记账数值”，可手动输入任意支持单位的价格。改变单位只更新元数据，不自动换算、清空或重载数字。
3. 可显式加载相应来源单位的基础价。只有单模型 Token 价卡支持加载，避免把一个型号的价目无意应用到多个型号；已有区间、分时及倍率保留。
4. 默认 USD 查询继续使用原来的模型价格服务。非 USD 查询只命中明确登记的原币价卡；缺少该单位/型号时返回 `found=false`，不通过比值推算，也不猜测未知型号别名。经营者可手填。
5. 加载期间的金额、模型、模式或单位变更使旧请求失效；加载失败或缺少数据保留当前数字。
6. 来源元数据经过 API、数据库、编辑表单、复制和采购规则路径持久化；销售与采购金额仍由同一套既有计算函数决定。

## 首批登记数据

`internal/service/nominal_price_presets.json` 是可扩展的数据登记表。首批 CNY 基础价来自已核验的 2026-11-02 本站运维配置快照，界面展示记录日期，不声称它是实时官方报价：

| 明确型号 | 未命中输入 / 百万 | 输出 / 百万 | 缓存读取 / 百万 |
| --- | ---: | ---: | ---: |
| deepseek-flash、deepseek-v4-flash、deepseek-v4.1-flash | 1 | 4 | 0.02 |
| deepseek-v4-pro | 4.5 | 13.5 | 0.15 |

导入仅填基础单价。峰谷、工作日时段及渠道销售加价仍由现有分时/倍率配置表达；其他上游的不同报价仍可手工覆盖，不自动统一。

新增其他币种/厂商价目只需要登记明确的原币数据。没有原币数据时，无法靠把默认美元价的符号改成 CNY 来恢复人民币价；例如美元与人民币公开价目可能经过不同舍入，不能假设所有模型与项目存在同一个精确比值。

## 兼容与发布

迁移 `255_nominal_price_source_currency.sql` 只为两个原始 SQL 价卡表添加可空来源语义的非空字符串列（默认空字符串），不更新金额。分组价卡已有 JSON 存储可直接保存该字段。旧镜像可继续忽略附加列和 JSON 字段，回滚镜像不需要回滚数据库或覆盖新写入。

上线前记录现有价卡及倍率指纹，演练新增迁移并备份数据库与配置。上线后核对来源币种的保存/回显、数字不变、真实流式/非流式推理及用量入账。已有原币价卡只在核对来源记录后补来源元数据，不自动改价，不追扣历史。

验证重点包括非 USD 来源的原数值计价、销售/采购路径、未知价卡不换算、来源字段持久化，以及延迟加载不会覆盖用户的新输入。
