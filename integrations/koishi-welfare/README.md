# QQ 机器人福利中心

变体：标准中性纸色 / 黄色强调 / 紧凑列表 / 短动效。
主视觉：网站展示真实积分、商品和记录；机器人图片仅显示积分和签到状态。
页面：网站用户福利中心、管理员控制台；QQ 用户收到静态 PNG。

网站后台 `/admin/qq-welfare` 管理群认证、积分商品、共享兑换码和最近 100 笔领取记录。用户福利中心 `/welfare` 提供首次群认证、每日签到、积分兑换、共享码领取与最近 100 笔记录；个人资料 `/profile` 也可生成认证码。机器人仅提供签到、积分查看及必要的认证命令。

## 设置和使用

1. 管理员保存允许认证的 QQ 群号并启用福利中心。
2. 生成群连接码，在该群内提及机器人并发送 `福利连接 连接码`。连接码有效十分钟、只能使用一次。QQ 官方提供的是不透明的群 OpenID，需要这次操作把实际群与配置关联。管理员只应在指定群使用连接码。
3. 用户登录网站，在福利中心或个人资料生成认证码，然后在已连接群提及机器人发送 `认证 认证码`。认证码有效十分钟、只能使用一次，生成间隔一分钟。一个 QQ 身份只绑定一个网站账号；认证码不得转发。首次认证长期有效，后续进入无需重新验证。网站和机器人共用积分及每日签到记录，合计每日仅能获得 1 积分。
4. 管理员创建积分商品或共享兑换码，检查积分价格、美元余额面值、库存 / 领取上限、截止时间，勾选上架并保存。新建默认为下架，系统不预设有价值的奖励。

群内提及机器人后使用：

| 命令 | 操作 |
| --- | --- |
| 积分 | 个人积分和今日签到状态一图流 |
| 签到 | 北京时间每天首次签到 +1 积分 |
| 认证 认证码 | 绑定登录的网站账号，长期有效 |
| 福利连接 连接码 | 管理员首次连接认证群 |

商品和共享码奖励为网站美元余额。领取时生成个人兑换凭证，在同一数据库事务内自动核销、入账并保存订单；群聊不会出现可被抢领的个人兑换码。凭证使用现有 `admin_balance` 类型，不计入付款或邀请返佣。共享码仅通过网站福利中心领取。机器人接口拒绝商品兑换和共享码领取，也不返回商品或领取记录。

网站交易使用请求编号实现幂等，同一请求重试只返回原订单；前端会保留未确认结果的请求编号。网站身份来自登录用户对应的群认证记录，不接受客户端指定 QQ 或群身份。账号、商品和共享码行锁配合唯一索引，防止重复签到、超卖和重复领取。库存或商品发生变化后，旧管理表单返回冲突，必须刷新重开再保存。下架再上架不重置领取记录。

更改认证群号会清除群连接，旧群认证停止生效，用户需在新群重新认证；原积分和订单保留。已绑定身份不开放自助换号。禁用网站账号或福利中心会阻止使用。签到和历史显示采用北京时间；管理截止时间输入按管理员浏览器本地时间转换为 UTC 保存。

## 私有桥接部署

需要 Koishi QQ 适配器、`puppeteer-core`、`/usr/bin/chromium`、Noto Sans CJK，以及原生后端迁移 `253_qq_welfare.sql`。

- 插件目录：`/opt/koishi/data/plugins/welfare-center`，复制本目录 JS、package.json 和 assets；在持久化 node_modules 建立 `koishi-plugin-welfare-center` 指向插件目录的链接。
- 宿主服务：复制 `bridge.py` 到 `/opt/koishi/welfare-center/bridge.py`，安装随附 systemd 单元。
- 启动服务前必须执行 `install -d -m 0700 /opt/koishi/data/welfare-center`。systemd 会在 Python 启动前验证 `ReadWritePaths`，不能依赖 Python 首次创建目录。
- 配置 Koishi `welfare-center` 插件后重启 Koishi；启用 `koishi-welfare-center.service`。修改前备份 Koishi 配置。
- socket `/opt/koishi/data/welfare-center/bridge.sock` 为 0600，父目录 0700。现有 `/opt/koishi/data` 已挂载到容器 `/koishi`。
- 桥接进程只查询专用 bot key，并向固定原生接口发送请求。Koishi 无数据库、Docker socket 或管理员密钥，不新增公网监听。
- `bridge.py` 的容器和数据库名称是部署约定，其他安装须按实际名称调整。专用 key 初始化在原生管理接口首次访问时，永不进入 JSON 响应。
- 升级前备份数据库、Koishi 配置和插件目录。停用插件和桥接服务后可回滚旧应用；新增表保留，勿删除订单和领取记录。

## 验证

后端 `TestQQWelfare*` 覆盖认证边界、输入验证、并发签到、事务回滚、事件重放、共享码每账号一次和库存过期编辑。真实 PostgreSQL 测试用 `integration` 标签进入现有测试容器；手工独立数据库可用 `welfareintegration` 标签和 `WELFARE_TEST_DSN`，禁止指向生产库。

在 Koishi 容器内执行 `node --test plugins/welfare-center/welfare.test.cjs`，检查平台身份、参数、HTML 转义和个人图片隔离。真实群 OpenID、提及机器人和平台消息投递仍须由群内实际命令验证。Saira 字体采用 SIL OFL，许可证随 assets 分发。
